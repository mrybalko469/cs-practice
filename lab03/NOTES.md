# Воркшоп по Git (lab03)

## 2. Сравнение версий и поиск изменений

- `git log --oneline --stat` — список коммитов в одну строку и какие файлы в каждом изменились и на сколько строк. Нужен, чтобы увидеть историю целиком.
- `git diff HEAD~2 HEAD -- lab03/calc.py` — разница между двумя состояниями файла: между первым и третьим коммитом добавились функции `sub` и `mul` и ветки `elif` для `-` и `*`.
- `git show HEAD~1` — один конкретный коммит: автор, дата, сообщение и его изменения (добавление вычитания).
- Отличие: `git diff` сравнивает два произвольных состояния (коммиты, рабочую папку, индекс); `git show` показывает один коммит и его изменения; `git log` показывает историю коммитов, а не содержимое изменений.
- `git log -S"def" --oneline -- lab03/calc.py` — ищет коммиты, где менялось число вхождений строки `def`. Нашёл три коммита, где добавлялись функции `add`, `sub`, `mul`.
- `git blame lab03/calc.py` — для каждой строки показывает, каким коммитом и кем она последний раз изменена. Видно, что строки с `mul` пришли из коммита про умножение.

## 3. Восстановление файла

- `git status` — показал `modified: lab03/calc.py`: файл изменён (удалены две строки), но не закоммичен.
- `git restore lab03/calc.py` — вернул файл к состоянию последнего коммита (HEAD); `git status` снова показал чистую рабочую папку.
- `git restore --source=HEAD~2 lab03/calc.py` — положил в рабочую папку версию файла из коммита на два назад (сложение и вычитание, без умножения). `git diff` показал, что по сравнению с HEAD пропали функция `mul` и ветка `elif d == "*"`. Сами коммиты при этом не меняются.
- Разница: без `--source` файл берётся из последнего коммита, с `--source=...` — из любого указанного коммита. В обоих случаях незакоммиченные правки в файле теряются безвозвратно, поэтому перед `restore` надо убедиться, что они не нужны.

## 4. Ошибочный коммит и его отмена

- `git log --oneline` — убедился, что коммит с делением без проверки нуля есть в истории.
- `git revert HEAD` — создал новый коммит «Revert ...», который отменяет изменения последнего коммита. Ошибочный коммит остался в истории, а в файле деления больше нет.
- `git reset --hard` передвигает ветку назад и выбрасывает коммиты и незакоммиченные правки — история переписывается.
- В опубликованной истории безопаснее `revert`: он ничего не удаляет, а добавляет коммит, поэтому у тех, кто уже скачал репозиторий, история не расходится и не нужен `push --force`.
